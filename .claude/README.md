# Agent และ workflow ประจำโปรเจกต์

ไฟล์ในโฟลเดอร์นี้ใช้กับ **Claude Code ตอนพัฒนา** เท่านั้น ไม่เกี่ยวกับตัวแอปที่แพทย์ประจำบ้านใช้งาน
และไม่ถูกโหลดเข้าหน้าเว็บใด ๆ

## agent 4 ตัว ใช้โมเดลคนละระดับตามงาน

| agent | โมเดล | ใช้ทำอะไร |
|---|---|---|
| `ortho-scan` | haiku | สำรวจเร็ว ๆ ว่าอะไรอยู่ตรงไหน อะไรเปลี่ยนบ้าง คืนข้อเท็จจริงพร้อม `path:line` ไม่วิเคราะห์ |
| `ortho-review` | sonnet | ตรวจสิ่งที่แก้เทียบกติกาของโปรเจกต์ (ไฟล์เดียว, ข้อมูลผู้ป่วย, สิทธิ์, กับดักที่เคยเจอ) |

เรียกใช้ทีละตัวได้เลย เช่น *“ใช้ ortho-scan หาว่าโค้ดส่วนจัดตารางหมุนเวียนอยู่ตรงไหน”*

## workflow ที่ร้อยสามขั้นเข้าด้วยกัน

`workflows/portfolio-check.js` — สำรวจ (haiku) → ตรวจ 4 มุมพร้อมกัน + ทดสอบเบราว์เซอร์ (sonnet) → ยืนยัน (opus)

```
เรียกใช้: "รัน workflow portfolio-check"           # ตรวจสิ่งที่ยังไม่ commit
          "รัน workflow portfolio-check กับ HEAD~1"  # ตรวจ commit ล่าสุด
```

ขั้นตรวจแยกเป็น 4 มุมที่ทำงานขนานกัน: ความเป็นส่วนตัวของข้อมูลผู้ป่วย · สิทธิ์ตามบทบาท ·
ความถูกต้องของตรรกะและการซิงก์ · กติกาไฟล์เดียวและกับดักที่เคยเจอ
ข้อค้นพบทั้งหมดถูกส่งให้ขั้นยืนยันหักล้างก่อน จึงเหลือเฉพาะสิ่งที่จริงพอจะลงมือแก้

## เลือกโมเดลอย่างไร

| งานแบบไหน | ใช้ | เหตุผล |
|---|---|---|
| หาโค้ด อ่าน diff เก็บข้อเท็จจริง รันคำสั่งซ้ำ ๆ | haiku | คำตอบตรวจสอบได้ทันทีจากเลขบรรทัด ไม่ต้องใช้การตัดสินใจ |
| ตรวจโค้ด เขียน/รันเทสต์ แก้บั๊กที่รู้อาการ อัปเดตเอกสาร | sonnet | ต้องเข้าใจบริบทแต่คำตอบยังพิสูจน์ได้ด้วยการรัน |
| หักล้างข้อค้นพบ สรุปว่าจะแก้อะไรก่อน | opus | ต้องชั่งน้ำหนักหลายข้อพร้อมกันและกล้าตัดข้อที่ไม่จริงทิ้ง |
| ตัดสินใจที่ย้อนกลับแพง หรือข้อจำกัดขัดกันเอง | fable | ราคาแพงที่สุด จึงคุ้มเฉพาะตอนที่ **ราคาของการเลือกผิดแพงกว่า** |

**ก่อนเรียก fable ให้ถามสามข้อ** — ถ้าตอบ "ไม่" ข้อใดข้อหนึ่ง แปลว่ายังไม่ต้องใช้

1. มีทางเลือกมากกว่าหนึ่งทางที่ฟังดูดีพอกันจริงหรือไม่ (ถ้ามีคำตอบเดียวชัด ๆ ให้ลงมือเลย)
2. ถ้าเลือกผิด ต้องรื้อของที่ทำไปแล้วหรือข้อมูลเสียหายย้อนไม่ได้ใช่หรือไม่
3. ปัญหานี้ตัดสินด้วยการ "ลองรันดู" ไม่ได้ใช่หรือไม่ (ถ้าลองแล้วรู้ผลทันที ให้ลองแทนที่จะคิด)

agent ทั้งสองตัวที่ใช้ fable ถูกเขียนให้ **ปฏิเสธงานที่ไม่คุ้ม** — ถ้าโจทย์เล็กเกินไป มันจะบอกกลับว่าให้ใช้ตัวไหนแทน

ตัวอย่างงานในโปรเจกต์นี้ที่คุ้มกับ fable จริง ๆ: ออกแบบการรวมข้อมูลระดับฟิลด์และการส่งเฉพาะส่วนที่เปลี่ยน ·
ออกแบบ schema กับลำดับการย้ายจากไฟล์เดียวไปเซิร์ฟเวอร์โดยไม่ทำข้อมูลเดิมหาย ·
ปรับตัวจัดตารางเมื่อเพิ่มเวร วันหยุด และการลาเข้ามาพร้อมกัน · วางโครงหลักฐาน WFME/EPA ตอนได้เอกสารจริง

## หมายเหตุ

- agent ที่เพิ่งเพิ่มจะใช้ได้ใน session ถัดไป (ทะเบียน agent อ่านตอนเริ่ม session)
- แต่ละ agent มีเครื่องมือจำกัดตามหน้าที่ — ตัวสำรวจ ตัวตรวจ และตัวยืนยัน **แก้ไฟล์ไม่ได้** มีแต่ `ortho-test` ที่เขียนไฟล์ทดสอบได้
- โมเดลที่กำหนดไว้เป็นค่าเริ่มต้นของแต่ละ agent สั่งเปลี่ยนเฉพาะครั้งได้ตอนเรียกใช้

## skill ของบุคคลที่สาม (ติดตั้งเอง ไม่ได้เก็บใน repo)

`skills-lock.json` ที่รากบันทึกไว้ว่าเคยติดตั้งอะไร ติดตั้งซ้ำได้ด้วย

```bash
npx skills add nutlope/hallmark                                  # แนวทางออกแบบหน้าเว็บ (markdown ล้วน)
npx skills add nextlevelbuilder/ui-ux-pro-max-skill@ui-ux-pro-max # ฐานข้อมูลกฎ UI/UX ค้นได้ในเครื่อง
```

ตัวไฟล์ลงที่ `.agents/skills/` และถูก ignore ไว้ เพราะเป็นเครื่องมือของผู้พัฒนาแต่ละคน รวมกันหลายเมกะไบต์
และตัวหนึ่งมีสคริปต์ Python ที่ควรให้แต่ละคนตรวจเองก่อนใช้ (ผู้ติดตั้งเตือนไว้ว่า skill ทำงานด้วยสิทธิ์เต็มของ agent)
