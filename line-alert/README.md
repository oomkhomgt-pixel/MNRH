# แจ้งเตือนสรุปกิจกรรมประจำวันเข้ากลุ่ม LINE

ส่งสรุปกิจกรรมของแพทย์ประจำบ้านทุกคนในวันนั้นเข้ากลุ่ม LINE ของภาควิชา **ครั้งเดียวต่อวัน** (ไม่ใช่ส่งแยกเป็นรายคน)
โดยเฉพาะคาบ **Topic conference** (พฤหัสบดี 09:00–12:00) จะขึ้นชื่ออาจารย์ผู้นิเทศและหัวหน้าสายของสัปดาห์นั้นด้วย

ส่วนนี้**แยกออกจากแอปหลัก (`portfolio/`) โดยตั้งใจ** — แอปหลักเป็นไฟล์เดียวรันในเบราว์เซอร์ ไม่มีเซิร์ฟเวอร์และไม่ยิง
network ออกนอกเครื่องเลยตามหลักการเดิมของโปรเจกต์ (ดู `portfolio/README.md`) แต่การส่งข้อความ LINE อัตโนมัติทุกวัน
ทำแบบนั้นไม่ได้จริง เพราะ (1) ต้องมีอะไรสักอย่างทำงานตามเวลาที่แน่นอนทุกวันแม้ไม่มีใครเปิดเบราว์เซอร์ค้างไว้ และ
(2) **LINE channel access token ต้องไม่อยู่ในโค้ดฝั่งไคลเอนต์เด็ดขาด** — ใครก็ตามที่เปิด devtools ของเบราว์เซอร์
จะขโมย token ไปยิงข้อความแทนบอทได้ทันที ส่วนนี้จึงรันบน GitHub Actions (เซิร์ฟเวอร์ของ GitHub) แทน

ไม่ต้องเป็นโปรแกรมเมอร์ก็ตั้งค่าได้ตามขั้นตอนด้านล่าง — ใช้เวลาประมาณ 15–20 นาที

## ภาพรวมการทำงาน

```
data-source.mjs  →  compute.mjs  →  format.mjs  →  line-client.mjs
(ข้อมูลวันนี้มาจากไหน)  (คำนวณตารางจริง)   (จัดเป็นข้อความไทย)   (ส่งเข้า LINE)
```

`compute.mjs` **ไม่ได้เขียนตรรกะจัดตารางขึ้นมาใหม่** — มันเปิด `portfolio/index.html` ตัวจริงแบบไม่มีหน้าจอ
(headless Chromium ผ่าน Playwright) แล้วเรียกฟังก์ชันคำนวณตารางตัวเดียวกับที่คนใช้งานเห็นในแอปทุกวัน
เพื่อไม่ให้ตรรกะสองฝั่งไม่ตรงกัน

## ขั้นที่ 1 — สร้างช่องทาง LINE (ฟรี)

1. เข้า [LINE Developers Console](https://developers.line.biz/console/) ด้วยบัญชี LINE ของภาควิชา (หรือของคนที่ดูแลระบบ)
2. สร้าง **Provider** ใหม่ (ถ้ายังไม่มี) เช่นชื่อ "ภาควิชาออร์โธปิดิกส์"
3. สร้างช่องทางประเภท **Messaging API** ภายใต้ Provider นั้น ตั้งชื่อบอทตามสะดวก เช่น "แจ้งเตือนตารางออร์โธ"
4. เข้าไปที่แท็บ **Messaging API** ของช่องทางที่สร้าง แล้วออก **Channel access token (long-lived)** — คัดลอกเก็บไว้
   (ค่านี้คือรหัสลับ ห้ามส่งต่อทางแชท/อีเมล ห้ามใส่ในไฟล์ไหนของโปรเจกต์เด็ดขาด)
5. ในหน้าเดียวกัน **ปิด** Auto-reply message และ Greeting message (ไม่จำเป็นสำหรับบอทที่ใช้แจ้งเตือนอย่างเดียว)

## ขั้นที่ 2 — เชิญบอทเข้ากลุ่ม LINE เดิมของแผนก

1. เปิดหน้า Messaging API ของช่องทาง จะมี QR code หรือ Bot ID ของบอท
2. เพิ่มบอทเป็นเพื่อน แล้ว **เชิญเข้ากลุ่ม LINE เดิมที่แผนกใช้อยู่** เหมือนเชิญคนทั่วไปเข้ากลุ่ม
3. บอทมองเห็นแค่ข้อความที่ mention มัน — จะไม่อ่านหรือตอบข้อความอื่นในกลุ่ม (Auto-reply ปิดไว้แล้วในขั้นที่ 1)

## ขั้นที่ 3 — หา Group ID ของกลุ่ม

LINE ไม่โชว์ Group ID ให้ดูตรง ๆ ในหน้าจอ ต้องอ่านจาก webhook ชั่วคราว:

1. ใช้บริการดักปลายทาง webhook ชั่วคราว เช่น [webhook.site](https://webhook.site) เปิดหน้าเว็บแล้วคัดลอก URL เฉพาะที่ได้
2. กลับไปที่ Messaging API ของช่องทางใน LINE Developers Console → ตั้ง **Webhook URL** เป็น URL จากข้อ 1 → เปิด
   "Use webhook"
3. เข้ากลุ่ม LINE ที่เชิญบอทไว้ แล้วพิมพ์ข้อความอะไรก็ได้ที่ mention บอท (เช่น `@ชื่อบอท สวัสดี`)
4. กลับไปดูที่หน้า webhook.site จะเห็น payload เป็น JSON — หาค่า `"groupId"` ข้างใน (อยู่ใต้ `"source"`) แล้วคัดลอกไว้
5. **ปิด "Use webhook"** กลับคืน (ไม่ต้องใช้ webhook อีกหลังจากขั้นนี้ เพราะบอทนี้ใช้ส่งอย่างเดียว ไม่ต้องรับ)

## ขั้นที่ 4 — ตั้งค่า GitHub Secrets

ในหน้า GitHub ของ repository นี้ → **Settings → Secrets and variables → Actions → New repository secret**
เพิ่มสองค่า:

| ชื่อ Secret | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | token จากขั้นที่ 1 |
| `LINE_GROUP_ID` | group ID จากขั้นที่ 3 |

ค่าทั้งสองจะไม่ถูกบันทึกลงไฟล์ในโปรเจกต์ที่ไหนเลย — GitHub Actions ดึงมาใช้ตอนรันเท่านั้น

## ขั้นที่ 5 — ทดสอบด้วย dry-run ก่อนเปิดใช้จริง

**อย่าเปิดใช้งานจริงจนกว่าจะเห็นข้อความตัวอย่างก่อน** ทดสอบได้สองทาง:

**ทางที่ 1 — บนเครื่องตัวเอง** (ต้องมี Node.js และเคย `npx playwright install chromium` มาก่อน):

```bash
cd line-alert
npm install
npm run dry-run
```

จะเห็นข้อความที่ *จะ* ส่งพิมพ์ออกมาในเทอร์มินัล โดยไม่ได้ยิงเข้า LINE จริง

**ทางที่ 2 — บน GitHub Actions** (ไม่ต้องมีอะไรติดตั้งในเครื่อง): ไปที่แท็บ **Actions** ของ repository →
เลือกเวิร์กโฟลว์ "แจ้งเตือน LINE รายวัน" → **Run workflow** → เลือก `dry_run: true` → Run
ดูผลลัพธ์ได้ในหน้า log ของรันนั้น

เมื่อข้อความหน้าตาถูกต้องแล้ว ค่อยรันแบบไม่ใส่ `--dry-run` (หรือเลือก `dry_run: false` บน Actions) เพื่อส่งจริง

## ขั้นตอนการทำงานประจำวัน

GitHub Actions รันให้อัตโนมัติทุกวันตามตารางใน `.github/workflows/line-daily-alert.yml` (ค่าเริ่มต้นคือ 07:00 น.
เวลาไทย) ไม่ต้องทำอะไรเพิ่ม **ยกเว้น** สองเรื่องนี้ที่ผู้จัดหลักสูตรต้องทำเองในแอปหลัก:

1. **กำหนดผู้นิเทศ Topic conference รายสัปดาห์** — หน้า "ตาราง: หมุนเวียน · เวร · นำเสนอ" → การ์ด
   "ผู้นิเทศ Topic conference รายสัปดาห์" (สิทธิ์ผู้จัดหลักสูตรเท่านั้น) ถ้าไม่ได้กำหนดไว้ ข้อความจะขึ้น
   "ยังไม่ได้กำหนด" แทนชื่อจริง
2. **ส่งออกข้อมูลล่าสุด** ให้ไปป์ไลน์นี้อ่าน (ดูหัวข้อถัดไป)

## ข้อมูล "วันนี้" มาจากไหน

จุดสลับแหล่งข้อมูลอยู่ที่ `data-source.mjs` ไฟล์เดียว — ตอนนี้ (ค่าเริ่มต้น) อ่านจากไฟล์ JSON ที่ export
ออกมาจากแอป:

1. เข้าแอปหลักด้วยบัญชีผู้จัดหลักสูตร → หน้าตั้งค่า → ปุ่ม **"สำรองข้อมูล"** → ได้ไฟล์ `ortho-portfolio-YYYY-MM-DD.json`
2. เก็บไฟล์นี้ไว้ที่ `line-alert/data/latest-export.json` (แทนที่ไฟล์ตัวอย่างที่แนบมาด้วย) หรือชี้ผ่าน
   ตัวแปรแวดล้อม `MNRH_DATASET_FILE=/path/to/file.json` หรือ `--file=/path/to/file.json`
3. อัปเดตไฟล์นี้ทุกครั้งที่ตารางเปลี่ยน (เช่นหลังกำหนดผู้นิเทศ Topic conference ใหม่) ก่อนที่ workflow จะรันรอบถัดไป
   — ไม่งั้นข้อความจะอ้างข้อมูลเก่า

**ข้อจำกัดของวิธีนี้**: ต้องมีคนอัปเดตไฟล์ export เองเป็นระยะ ๆ ถ้าอยากให้ข้อมูลสดเสมอโดยไม่ต้อง export มือ
ให้เปลี่ยนไปดึงจาก `sync-server/` (ดู `../sync-server/README.md`) แบบสดแทน — แก้แค่ฟังก์ชัน
`loadTodayDataset()` ใน `data-source.mjs` ให้เป็น:

```js
const res = await fetch(url + "/api/portfolio/dataset");
const json = await res.json();
return json.data;
```

ส่วนที่เหลือทั้งหมด (`compute.mjs` / `format.mjs` / `line-client.mjs`) **ไม่ต้องแก้อะไรเลย** เพราะรับแค่
"object รูปร่างเดียวกับ `store.data`" เป็น input ไม่สนใจว่ามันมาจากไฟล์หรือจากเซิร์ฟเวอร์

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
|---|---|
| `data-source.mjs` | จุดสลับแหล่งข้อมูลเดียว (ดูหัวข้อข้างบน) |
| `compute.mjs` | เปิด `portfolio/index.html` จริงแบบไม่มีหน้าจอ คำนวณตารางของวันนั้น |
| `format.mjs` | จัดข้อความภาษาไทย (ไม่มีตรรกะจัดตารางในไฟล์นี้) |
| `line-client.mjs` | ส่งเข้า LINE push API + โหมด dry-run |
| `send-daily-alert.mjs` | จุดเริ่มที่เรียกจาก CLI/GitHub Actions ต่อทุกไฟล์ข้างบนเข้าด้วยกัน |
| `smoke.test.mjs` | ทดสอบที่ไม่ต้องมี credential จริง ไม่ยิง network — รันก่อนยิงจริงทุกครั้ง |
| `data/latest-export.json` | ไฟล์ข้อมูลตัวอย่าง/ตั้งต้น (แทนที่ด้วยไฟล์ export จริงของแผนกตามขั้นตอนข้างบน) |

## คำสั่งที่ใช้บ่อย

```bash
npm install                              # ติดตั้ง dependency (playwright) ครั้งแรก
npm test                                 # รัน smoke test (ไม่ยิง network, ไม่ต้องมี credential)
npm run dry-run                          # จำลองส่ง อ่านข้อความออกมาดูก่อนเปิดใช้จริง
node send-daily-alert.mjs --date=2026-09-03   # ทดสอบของวันที่ระบุเอง (เช่นวันพฤหัสฯ ที่มี Topic conference)
```
