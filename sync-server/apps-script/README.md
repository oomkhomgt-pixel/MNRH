# คลาวด์ของภาควิชาบน Google Drive (Apps Script)

ปลายทางสำหรับโหมด “ฐานข้อมูลกลางของภาควิชา” ที่เก็บข้อมูลทั้งชุดเป็นไฟล์เดียวในโฟลเดอร์บน Drive ของภาควิชา
ใช้คู่กับ **การเข้ารหัสข้อมูลบนคลาวด์** ในแอป — ไฟล์บน Drive เป็นข้อมูลที่อ่านไม่ออก สคริปต์นี้ไม่มีกุญแจและไม่ต้องมี

> ก่อนเก็บข้อมูลผู้ป่วย (HN) ให้ยืนยันกับเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ของโรงพยาบาลว่า
> บัญชี Google Workspace ของภาควิชาได้รับอนุญาตให้เก็บข้อมูลชนิดนี้ (ดูหัวข้อ “สำหรับ DPO” ท้ายไฟล์)

## ติดตั้ง (ครั้งเดียว ใช้บัญชีของภาควิชา)

1. สร้างโฟลเดอร์ใหม่บน Drive ของภาควิชา เช่น `portfolio-cloud` — **อย่าแชร์โฟลเดอร์นี้ให้ใคร**
   คัดลอกรหัสโฟลเดอร์จาก URL (ส่วนหลัง `/folders/`)
2. เปิด <https://script.google.com> → New project → วางเนื้อหา `Code.gs` ทับทั้งไฟล์
3. Project Settings (รูปเฟือง) → Script Properties → Add
   - `FOLDER_ID` = รหัสโฟลเดอร์จากข้อ 1
   - `KEEP_VERSIONS` = `20` (จำนวนสำเนารุ่นก่อนหน้าที่เก็บไว้ — ใช้กู้เมื่อมีคนส่งข้อมูลผิด)
   - สคริปต์รับเฉพาะข้อมูลที่เข้ารหัสแล้วเป็นค่าเริ่มต้น **อย่าตั้ง `ALLOW_PLAINTEXT`** เมื่อมีข้อมูลจริง
4. สร้างโทเคนให้ผู้ดูแลแต่ละคน: ในหน้าแก้สคริปต์ แก้ชื่อใน `createTokenForAdmin()` ให้ตรงกับชื่อบัญชีในแอป
   แล้วเลือกฟังก์ชันนั้น → Run → โทเคนแสดงใน Execution log **ครั้งเดียว** (ระบบเก็บแค่ค่าแฮช)
   ทำซ้ำทีละคน · ถอนสิทธิ์ด้วย `revokeToken("ชื่อบัญชี")`
5. Deploy → New deployment → Web app
   - Execute as: **Me** (บัญชีภาควิชา)
   - Who has access: **Anyone** — จำเป็น เพราะเบราว์เซอร์เรียกข้ามโดเมนพร้อมการล็อกอิน Google ไม่ได้
     การกันคนนอกจึงอยู่ที่โทเคน และข้อมูลที่อ่านไม่ออกเพราะเข้ารหัส
   - คัดลอก URL ที่ลงท้าย `/exec`
6. ในแอป (ผู้ดูแลแต่ละคน บนเครื่องของตัวเอง): ตั้งค่า › ซิงก์ → โหมด “ฐานข้อมูลกลางของภาควิชา”
   - ที่อยู่คลาวด์ = URL จากข้อ 5 · โทเคน = โทเคนของคนนั้นจากข้อ 4 → “บันทึกและซิงก์เลย”
   - ถ้ายังไม่ได้เปิดการเข้ารหัส แอปจะ **ไม่ส่งอะไรขึ้นไป** และพาไปหน้าตั้งการเข้ารหัสแทน
7. ผู้ดูแลคนแรก: ตั้งรหัสผ่านของตัวเอง → **หัวหน้าภาควิชาจดกุญแจกู้คืน** → ยืนยัน 4 ตัวสุดท้าย → แอปเข้ารหัสและส่งขึ้น
8. เพิ่มผู้ดูแลคนอื่น: ผู้ดูแลที่ปลดล็อกแล้วเลือกบัญชี → ตั้งรหัสชั่วคราว → บอกเจ้าตัวต่อหน้า
   เจ้าตัวกด “ปลดล็อกเครื่องนี้” ด้วยรหัสชั่วคราว แล้วแอปบังคับให้ตั้งรหัสของตัวเอง

แก้สคริปต์ภายหลัง: Deploy → Manage deployments → แก้ deployment เดิม → Version: New version (URL เดิม)

### ถ้าเคยส่งข้อมูลที่ไม่ได้เข้ารหัสขึ้นโฟลเดอร์ไปแล้ว (เช่น ใช้สคริปต์รุ่นก่อน)

ไฟล์ `dataset.json` ที่ถูกเขียนทับยังเก็บรุ่นเดิมไว้ในประวัติรุ่นของ Drive และ `dataset-rN.json` ก็เป็นสำเนาเปิด
— ลบไฟล์ทีละไฟล์ไม่พอ ให้ย้ายไปใช้ **โฟลเดอร์ใหม่** (แก้ `FOLDER_ID`) แล้วให้ผู้ดูแลที่ปลดล็อกแล้วส่งขึ้นใหม่ (เข้ารหัส)
จากนั้นลบโฟลเดอร์เก่าทั้งโฟลเดอร์และ **ล้างถังขยะ** ของบัญชีภาควิชา

## งานประจำ

| เรื่อง | ทำอย่างไร |
|---|---|
| ผู้ดูแลลืมรหัสผ่าน | หัวหน้าภาควิชาใส่กุญแจกู้คืน (“ใช้กุญแจกู้คืน”) → ตั้งรหัสชั่วคราวใหม่ให้คนนั้น |
| ผู้ดูแลลาออก / เครื่องหาย / ลดบทบาท | ผู้ดูแลอีกคน “ถอด” คนนั้น (ออกกุญแจข้อมูลใหม่ทันที) และ `revokeToken` ในสคริปต์ — หน้าการเข้ารหัสติดป้ายเตือนผู้ถือกุญแจที่ไม่ได้เป็นผู้ดูแลแล้ว |
| ใช้เครื่องร่วมกันหลายคน | กุญแจในเครื่องแยกตามบัญชี คนที่ล็อกอินต่อใช้กุญแจของคนก่อนไม่ได้ · ปุ่ม “ล็อกเครื่องนี้” ลบเฉพาะกุญแจของบัญชีที่ล็อกอิน |
| สงสัยว่ารหัสของใครรั่ว | ถอดออกก่อน แล้วค่อยเพิ่มกลับด้วยรหัสชั่วคราว (ไม่ใช่แค่ตั้งรหัสใหม่) |
| มีคนส่งข้อมูลผิดทับ | ไฟล์ `dataset-rN.json` ในโฟลเดอร์คือรุ่นก่อนหน้า — ย้ายกลับเป็น `dataset.json` (ยังเข้ารหัสอยู่) |
| ดูว่าใครเข้าถึงเมื่อไร | Apps Script › Executions — บันทึกทุกการอ่าน/เขียนพร้อมชื่อบัญชีของโทเคน |

## ข้อจำกัดที่ควรรู้

- **ลืมรหัสผ่านทุกคนและกุญแจกู้คืนหาย = ข้อมูลบนคลาวด์กู้ไม่ได้** (ข้อมูลที่อยู่ในเครื่องของผู้ดูแลยังอยู่ ส่งขึ้นใหม่ได้)
- รหัสผ่านการเข้ารหัสต้องยาวอย่างน้อย 12 ตัวอักษร — คนที่ได้ไฟล์บน Drive ไปจะลองเดารหัสแบบออฟไลน์ได้
  ความปลอดภัยจึงขึ้นกับความยาวของรหัส (ใช้ประโยคยาว ๆ ไม่ซ้ำกับรหัสอื่น)
- คนที่ถูกถอดยังมีข้อมูลที่เคยอยู่ในเครื่องของเขา และสำเนารุ่นเก่าบน Drive ยังเปิดได้ด้วยกุญแจรุ่นเก่า
  (ถ้าจำเป็น ลบไฟล์ `dataset-rN.json` รุ่นก่อนการถอดออก)
- ข้อมูลในเครื่องของผู้ดูแลไม่ได้เข้ารหัส — ระดับ “ไม่เก็บ HN” และการล็อกหน้าจอเครื่องยังเป็นด่านหลักบนอุปกรณ์
- ขนาดข้อมูลทั้งชุดต้องไม่เกิน 10 MB (หลังบีบอัดและเข้ารหัส)

## รายละเอียดทางเทคนิค

- ข้อมูล: AES-256-GCM (WebCrypto ในเบราว์เซอร์) บีบอัด gzip ก่อนเข้ารหัส
- ผู้ดูแลแต่ละคน: คู่กุญแจ ECDH P-256 — กุญแจส่วนตัวห่อด้วย PBKDF2-SHA256 600,000 รอบจากรหัสผ่าน
  กุญแจข้อมูลห่อแยกให้กุญแจสาธารณะของแต่ละคน (ถอดคนออกแล้วออกกุญแจใหม่ได้โดยไม่ต้องรู้รหัสของคนอื่น)
- รายชื่อผู้ถือกุญแจผูกกับการตรวจความถูกต้องของข้อมูล (AAD) — เติมช่องของคนนอกเข้าไปไม่ได้
  และเลขรุ่นกุญแจ (epoch) กันการนำสำเนาเก่าที่ยังมีคนที่ถูกถอดแล้วมาวางทับ
- ในเครื่องเก็บกุญแจส่วนตัวแยกตามบัญชีแบบส่งออกไม่ได้ (IndexedDB) · กุญแจข้อมูลอยู่ในหน่วยความจำเท่านั้น
- เปลี่ยนรหัสผ่าน = ออกคู่กุญแจใหม่ (คนที่เคยรู้รหัสชั่วคราวแกะกุญแจใหม่ไม่ได้) · ช่องที่ยังเป็นรหัสชั่วคราวส่งข้อมูลไม่ได้จนกว่าจะเปลี่ยน
- สคริปต์ปฏิเสธการเขียนข้อมูลที่ไม่ได้เข้ารหัสทับชุดที่เข้ารหัสแล้ว (กันแอปรุ่นเก่า) · แอปก็ไม่รับข้อมูลไม่เข้ารหัสจากคลาวด์
  เมื่อเปิดใช้แล้ว

## สำหรับ DPO

- ข้อมูลที่เก็บ: ทะเบียนแพทย์ประจำบ้าน/อาจารย์ ผลประเมิน กิจกรรม และ logbook เคสผ่าตัด (HN อายุ เพศ diagnosis operation)
- ที่เก็บ: ไฟล์ในโฟลเดอร์บน Google Drive ของบัญชีภาควิชา — **เข้ารหัสก่อนออกจากเครื่อง** กุญแจอยู่กับผู้ดูแลที่ได้รับมอบหมาย
  และหัวหน้าภาควิชาเท่านั้น Google และผู้ที่เข้าถึงโฟลเดอร์ได้เห็นแต่ข้อมูลที่อ่านไม่ออก
- ผู้เข้าถึง: ผู้ดูแลที่มีทั้งโทเคน (ถอนได้รายคน) และรหัสผ่านการเข้ารหัส (ถอดได้รายคน) · บันทึกการเข้าถึงใน Apps Script Executions
- ประเด็นที่ DPO ต้องพิจารณา: ฐานทางกฎหมายสำหรับข้อมูลสุขภาพ (มาตรา 26) · การเก็บบนเซิร์ฟเวอร์นอกประเทศ (มาตรา 28)
  · ระยะเวลาเก็บ · การแจ้งเหตุละเมิดภายใน 72 ชั่วโมง (มาตรา 37) — การเข้ารหัสที่กุญแจไม่รั่วช่วยลดความเสี่ยง แต่ไม่ใช่ข้อยกเว้น
