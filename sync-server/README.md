# เซิร์ฟเวอร์อ้างอิงสำหรับซิงก์ logbook

ตัวอย่างเล็ก ๆ ที่แสดง **สัญญาข้อมูล (contract)** ที่หน้าแฟ้มสะสมงานใช้ซิงก์ logbook ขึ้นระบบกลาง
ไม่ได้ตั้งใจให้ใช้งานจริงตามที่เป็น — ของจริงควรผูกกับบัญชีผู้ใช้ของโรงพยาบาลและอยู่หลัง TLS

```bash
node server.js                                    # ฟัง :8090 เก็บไฟล์ data.json ข้าง ๆ
PORT=9000 ALLOW_ORIGIN='https://portfolio.hospital.local' \
  TOKENS='{"resident01":"…"}' node server.js
```

## สัญญาข้อมูล

| วิธี | เส้นทาง | เนื้อหา |
|---|---|---|
| `PUT` | `/api/portfolio/logbook` | `{ user, updatedAt, items: [{ ref, date, diagnosis, operation, role? }] }` → `{ ok, stored }` |
| `GET` | `/api/portfolio/logbook?user=…` | → `{ user, updatedAt, items[] }` |

**สิ่งที่ส่งออกมีเพียง วันที่ผ่าตัด, diagnosis, operation** (และ `role` เมื่อผู้ใช้เปิดไว้) —
ไม่มี HN ไม่มีชื่อผู้ป่วย ไม่มีอายุ/เพศ และไม่มีชื่อศัลยแพทย์ เซิร์ฟเวอร์นี้ยัง **ตัดฟิลด์อื่นทิ้งอีกชั้นหนึ่ง**
ก่อนบันทึก เพื่อกันข้อมูลที่ไม่ได้ตกลงกันหลุดเข้ามาโดยไม่ตั้งใจ

`ref` คือเลขที่เคสของระบบคิวห้องผ่าตัด ใช้กันรายการซ้ำและใช้อ้างอิงกลับเมื่ออยู่ในโรงพยาบาลเท่านั้น
ตัวมันเองไม่บอกว่าเป็นผู้ป่วยรายใด

## ชุดข้อมูลทั้งก้อน (ฐานข้อมูลกลางของภาควิชา)

| วิธี | เส้นทาง | เนื้อหา |
|---|---|---|
| `PUT` | `/api/portfolio/dataset` | `{ device, updatedAt, data }` → `{ ok, updatedAt, bytes, versions }` |
| `GET` | `/api/portfolio/dataset` | → `{ updatedAt, device, data }` |
| `GET` | `/api/portfolio/dataset?versions=1` | → `{ versions: [{ at, device, bytes }] }` |

ใช้กับโหมด “ฐานข้อมูลกลางของภาควิชา” ในหน้าซิงก์ · เซิร์ฟเวอร์นี้เก็บเวอร์ชันย้อนหลัง 10 รุ่น
(ตั้งได้ด้วย `KEEP_VERSIONS`) และเขียนทับทั้งชุดตามที่ส่งมาล่าสุด — ของจริงควรทำการรวมข้อมูลรายรายการ
และเก็บประวัติการแก้ไขต่อผู้ใช้แทนการเขียนทับ

## ถ้าจะทำของจริง

- ผูก `user` กับบัญชีของโรงพยาบาล (SSO / บัญชีเดียวกับระบบคิว) แทนโทเคนในไฟล์
- ใส่ TLS, บันทึกการเข้าถึง, สำรองข้อมูล และกำหนดอายุการเก็บตามระเบียบของโรงพยาบาล
- ให้สิทธิ์ตามบทบาท: เจ้าของ logbook แก้ของตัวเอง อาจารย์ดูของผู้เข้าฝึกอบรมในความดูแล ผู้จัดหลักสูตรดูภาพรวม
- ทางที่ประหยัดที่สุดคือเพิ่มเส้นทางนี้เข้าไปในเซิร์ฟเวอร์ของระบบคิวที่มีระบบผู้ใช้อยู่แล้ว
