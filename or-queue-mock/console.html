อาการเสียที่ตั้งค้างไม่มี
นี่คือ ตัวจำลอง ของระบบคิวห้องผ่าตัด ไม่ใช่ระบบจริง ข้อมูลผู้ป่วยสมมติทั้งหมด (HN ขึ้นต้น MOCK-) มีไว้ให้ทดสอบการนำเข้าเคสของหน้าแฟ้มสะสมงานได้โดยไม่ต้องอยู่ใน intranet ของโรงพยาบาล

รายละเอียดเคส — ทุกฟิลด์ที่ตัวจำลองส่งออกมา

ประวัติ

คำขอที่ตัวจำลองได้รับ อัปเดตเองทุก 1.5 วินาที · เก็บ 200 รายการล่าสุด · ปิดเซิร์ฟเวอร์แล้วหาย

เปิดหน้านี้ค้างไว้ แล้วไปกด ดึงจาก API ในหน้าแฟ้มสะสมงาน จะเห็นว่าหน้าแฟ้มถามอะไรมาบ้าง และตัวจำลองตอบอะไรกลับไป — ใช้ดูว่าที่นำเข้าไม่ครบเป็นเพราะถามผิดหรือเพราะข้อมูลไม่มี

เวลาคำขอqueryผลหมายเหตุ
ยังไม่มีคำขอเข้ามา

ตั้งอาการเสียไว้ล่วงหน้า

กดปุ่มแล้วไปกด ดึงจาก API ในหน้าแฟ้ม คำขอถัดไปจะเจออาการที่เลือก ใช้ดูว่าหน้าแฟ้มบอกสาเหตุถูกไหม ไม่ต้องแก้ที่อยู่ API เอง

อีกทางหนึ่งคือต่อท้ายที่อยู่ API เอง เช่น /api/cases?_fail=500 — ชุดทดสอบอัตโนมัติใช้ทางนี้ ส่วนปุ่มข้างบนมีไว้ตอนสาธิตให้คนดู

ฟิลด์ไหนถูกนำเข้า ฟิลด์ไหนถูกทิ้ง

เทียบจากเคสจริงที่ตัวจำลองส่งออกมา กับรายการฟิลด์ที่ normaliseQueueCase() ในหน้าแฟ้มอ่าน

ฟิลด์ค่าตัวอย่างหน้าแฟ้ม

ต่อหน้าแฟ้มสะสมงานเข้ากับตัวจำลองนี้

  1. เปิดหน้าแฟ้มสะสมงาน (portfolio/index.html) แล้วเข้าสู่ระบบเป็น ผู้จัดหลักสูตร หรือ อาจารย์แพทย์
  2. ไปที่ Logbook เคสผ่าตัด → ตั้งค่าการเชื่อมต่อ
  3. ใส่ที่อยู่ API เป็น เส้นทางปล่อยไว้ตามเดิม (/api/cases?scope=all&includeClosed=true)
  4. เลือก ระดับข้อมูลผู้ป่วย แล้วกด ดึงจาก API
  5. กลับมาดูแท็บ คำขอที่เข้ามา ในหน้านี้
ตัวจำลองผูกกับ 127.0.0.1 เท่านั้น เครื่องอื่นในเครือข่ายเรียกไม่ได้ และไม่มีการยืนยันตัวตน — ใช้บนเครื่องพัฒนาเท่านั้น
